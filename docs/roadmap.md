# ATENOR System: hoja de ruta de documentación

Propuesta para mantener una presentación útil y verificable. No representa un calendario de desarrollo ni certifica funciones disponibles.

## Punto de partida

SaaS en evolución · desde marzo de 2026.

## Próximos entregables públicos

- Describir casos genéricos de operación sin nombres ni mensajes privados.
- Documentar reglas de negocio con entradas, resultado esperado y excepciones.
- Precisar límites de intervención automática y validación humana para cada caso.

## Criterios de aceptación

- Cada caso identifica el contexto del negocio y evita cruces de información.
- Automatizaciones describen qué sucede ante errores y cuándo intervenir.
- Ejemplos no contienen teléfonos, tokens, conversaciones ni identificadores de clientes.
- Enlaces locales, SVG y JSON pasan validación antes de publicación.
- Capturas o demostraciones solo se incorporan si tienen autorización de publicación.

## Actualización de estado

Para cambiar el estado público: describir qué cambió, aportar una referencia revisable, indicar limitaciones y obtener validación del responsable del producto. Evitar convertir planes en afirmaciones de resultados.
